# Windows VFIO Session Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a TTY command that dynamically gives Jezrien's RX 9070 XT and selected USB devices to a Windows 11 virtual machine, then returns the GPU to Linux without a normal reboot.

**Architecture:** Replace the legacy VFIO file with a dendritic NixOS module that exports `flake.modules.nixos.vfio`. A tested Python controller owns preflight, PCI driver changes, libvirt lifecycle, rollback, installation, and USB reconnection. Jezrien imports the module and supplies only its PCI addresses and USB identities.

**Tech Stack:** NixOS modules, flake-parts dendritic modules, import-tree, Python 3 standard library, systemd, Polkit, udev, libvirt/QEMU/KVM, OVMF, swtpm, qcow2, VirtIO.

**Spec:** `docs/superpowers/specs/2026-10-11-windows-vfio-session-design.md`

## Global Constraints

- Do not run `nixos-rebuild`, `home-manager switch`, or another activation command.
- `nix flake check` and `nix build` are allowed.
- The normal boot must bind `0000:2f:00.0` to `amdgpu` and `0000:2f:00.1` to `snd_hda_intel`.
- The service must select PCI devices by full address, never by vendor and product ID.
- The VM must expose normal KVM virtualization. Do not conceal the hypervisor or bypass anti-cheat.
- The Windows disk must be a 500 GiB thin-provisioned qcow2 file under `/var/lib/libvirt/images`.
- The VM must use Q35, OVMF Secure Boot, TPM 2.0, host CPU passthrough, 16 virtual CPUs, and 32 GiB memory.
- The VM must receive the RX 9070 XT, display audio, and the five approved runtime USB identities.
- Missing USB devices must not prevent VM startup.
- The implementation must not expose a host disk or `/home/dusty` to Windows.
- A failed preflight must not change any driver.
- Every failure after GPU detachment must attempt one idempotent return sequence. A normal reboot is the only fallback after return failure.

## Review Focus

- A graphical process opens the DRM node between preflight and unbind. The controller must stop before it changes the driver or restore Linux ownership.
- QEMU fails after both PCI functions bind to `vfio-pci`. The controller must restore audio, graphics, and console state.
- The KVM disconnects and reconnects the ZSA or Razer device. The udev helper must attach one configured device once and ignore an inactive domain.
- The install command runs twice. It must preserve the disk, UEFI variables, and an existing copied ISO unless the user supplies a new ISO explicitly.
- The GPU returns with a changed DRM node number. The controller must identify the PCI device through sysfs instead of assuming `/dev/dri/card0` or `card1`.

### Task 3: Dendritic NixOS VFIO module

**Files:**
- Modify: `modules/virtualization/vfio.nix`
- Remove: `modules/virtualization/virtman.nix`

**Interfaces:**
- Consumes: `config.ryk.username` from `self.modules.nixos.meta` and the runtime and XML files from Tasks 1 and 2.
- Produces: `flake.modules.nixos.vfio`.
- Produces options: `ryk.vfio.enable`, `ryk.vfio.domainName`, `ryk.vfio.gpu.pciAddress`, `ryk.vfio.gpu.linuxDriver`, `ryk.vfio.audio.pciAddress`, `ryk.vfio.audio.linuxDriver`, `ryk.vfio.memoryMiB`, `ryk.vfio.vcpus`, `ryk.vfio.diskSizeGiB`, and `ryk.vfio.usbDevices`.
- Produces commands: `windows-vm [--check]` and `windows-vm-install <windows-iso>`.
- Produces services: `windows-vm.service` and a udev-triggered `windows-vm-usb-attach@.service`.

- [ ] **Step 1: Add a failing flake check for controller tests and XML contracts**

Add a Linux-only `perSystem.checks.windows-vfio` derivation to `vfio.nix`. It must run all Python tests, render test XML, run `virt-xml-validate`, and fail on Python syntax errors.

Expected: FAIL while the old module lacks the check and new module wiring.

- [ ] **Step 2: Replace the legacy module with the dendritic module**

Keep the file-level export `flake.modules.nixos.vfio`. Gate all NixOS configuration with `lib.mkIf cfg.enable`. Generate a read-only JSON configuration and both rendered XML files in the Nix store. Package `windows_vm.py` as `windows-vm-control` with Python 3.

- [ ] **Step 3: Configure current libvirt, OVMF, TPM, and packages**

Move the supported settings from `virtman.nix` into the new module. Enable system libvirt with QEMU, swtpm, and Secure Boot OVMF. Install `libvirt`, `qemu`, `swtpm`, `virtio-win`, and the two user commands. Do not add early `vfio-pci.ids` kernel parameters.

- [ ] **Step 4: Add the service, Polkit rule, and commands**

Configure `windows-vm.service` as a root service with an infinite start timeout and explicit runtime paths. The service calls `windows-vm-control run` and owns cleanup. Allow only `config.ryk.username` in an active local session to start this exact unit through `org.freedesktop.systemd1.manage-units`. Make `windows-vm --check` call the unprivileged preflight directly. Make normal `windows-vm` start and wait for the service. Make `windows-vm-install` call the privileged prepare command through the user's existing sudo access, then start the same service.

Generate udev rules only for configured USB identities. Encode vendor and product IDs in the systemd instance argument. The template service calls `windows-vm-control attach-usb`. Reject identities that are not in the generated JSON allowlist.
